# Teacher similarity report restoration

1. **Original component:** `src/pages/HighlightedText.js` contains the screenshot's toolbar, legend, contained transcription, and source inspector. It remains used by the manual scan view.
2. **Cause:** Git history (`0c14b92`) shows `SubmissionReview.js` rendering an editable textarea and separate score/details instead of that component. The component was not deleted. Existing working-tree changes already introduced a read-only exact-evidence renderer; this restoration extends those changes. The old component's title/snippet keyword guesses and whitespace rewriting were intentionally not carried into submission review.
3. **Files:** `TeacherDashboard.js`, `dashboard/SubmissionReview.js`, `dashboard/EssayEvidence.js`, `dashboard/ClassmateMatches.js`, `dashboard/similarityEvidence.js`, and `workspace-theme.css`; associated report, peer, and evidence tests; `backend/match_evidence.py` and its test.
4. **API percentage:** Uses stored `score`, with `plagiarism_score` compatibility fallbacks. Never derived from source count, peer scores, or highlighted words. Zero is valid; failed, pending, stale, and classroom-only results do not display a successful online percentage.
5. **Source count:** Number of source records in `matchedSources` or legacy `result_data.matched_sources`, independent of passage count.
6. **Controls:** All shows online and scoped peer evidence; Sources hides peer evidence; Plain renders the unchanged text without marks. Switching modes does not invoke scanning.
7. **Yellow highlights:** Valid offsets bound to the scanned text take priority; otherwise exact passages are mapped. Ambiguous repeated external phrases without explicit occurrence evidence remain unresolved. Source titles and summary snippets never generate highlights.
8. **Pink highlights:** Existing peer snippets map to text only after matching classroom and assignment IDs and excluding the same student. Combined evidence uses both colors.
9. **Underlining:** Only explicit `matched_words` or `overlapping_keywords` arrays within a proven matched passage create keyword emphasis. Numeric word counts do not. Overlap boundaries are split into flat segments without nested marks.
10. **Source relationship:** Each range retains its source object, identifier, title, URL, domain, and available source score. Legacy passage identifiers/URLs reconnect to matching source records.
11. **Inspection:** Mouse or keyboard opens inline source details. View Source opens valid HTTP(S) URLs in a separate tab. View Match restores All mode, scrolls to the linked passage, and opens it. Peer inspection remains available.
12. **Canonical text:** One `review-transcription` element, preserving paragraphs and characters in every mode. Copy text receives the complete canonical transcription. The model badge uses the backend health configuration rather than a hardcoded model name.
13. **Read-only review:** No Teacher essay edit control, textarea, save-text handler, or transcription mutation request in the submission review flow. Grading and feedback remain editable.
14. **Classwork:** Online/Peer previews and Review Submission routing retained.
15. **Export:** Existing Subject, Assignment, Student Name, Grade structure and case-insensitive surname ordering retained; export/sort regression tests pass.
16. **Themes and layout:** Shared theme variables control surfaces, borders, text, and yellow/pink palettes. Toolbar and legend wrap; the transcription scrolls vertically with long-word wrapping. Peer review sits beneath the highlight panel and grading follows the report.
17. **Tests:** Added filter switching, source identity, four-source count, one canonical text, dynamic model label, no-peer state, explicit keyword overlap, and invalid backend offset coverage. Updated asynchronous source-inspection assertion.
18. **Verification:** Seven targeted frontend suites passed across the test runs (report, evidence, peer section, preview, workspace, export, sorting). Backend evidence/checker/status tests passed; the additional invalid-range test also passed. Production build passed with existing lint warnings (unused declarations, dependency warnings, and a duplicate avatarUrl key outside this change). No live authenticated browser or production API verification was performed.
19. **Storage:** Existing compact evidence export/storage pipeline remains. The backend now rejects out-of-bounds ranges instead of clipping them. No new migration is required. The existing `submission_match_evidence.sql` migration is still a prerequisite for stored evidence; its production application was not verified. Older results without evidence show the required unavailable-passages message.
