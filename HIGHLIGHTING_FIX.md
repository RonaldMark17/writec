Matched-text highlighting fix

1. Root cause: commit `0c14b92` replaced the teacher review's `HighlightedText` call with a plain textarea. The subsequent evidence renderer handled only a few evidence shapes and had no click interaction. The backend's completed-callback normalization retained summary scores/sources but did not export detailed Copyleaks comparison ranges. Scan submission also trimmed text, while the canonical saved text could retain leading/trailing whitespace.

2. Old implementation: `src/pages/HighlightedText.js`, called in the review before `0c14b92`. It used `highlighted_sentences`, nested `result_data.highlighted_sentences`, source title/snippet overlaps, and `peerSimilarity.matching_snippets`. It joined paragraphs and matched sentence prefixes. Its source-title inference was not safe to restore. The existing exact peer consecutive-word mapping in `PeerSimilarityReview.phraseRanges` is reused instead.

Files changed for this follow-up: `src/pages/dashboard/similarityEvidence.js`, `SubmissionReview.js`, new `EssayEvidence.js`, `src/workspace-theme.css`; `backend/copyleaks_service.py`, `submission_checker.py`, `submission_status.py`, `main.py`, new `match_evidence.py`; new `submission_match_evidence.sql`. Tests: `similarityEvidence.test.js`, `SubmissionReview.test.js`, new `EssayEvidence.test.js`, `TeacherDashboard.workspace.test.js`, `backend/test_submission_status.py`, new `backend/test_match_evidence.py`, and `scripts/test-revisions.cjs`. The earlier Classwork, sorting, export and editing changes remain in the working tree.

4. Online evidence: saved `highlighted_sentences` / `result_data.highlighted_sentences`; `matchedSources` / `result_data.matched_sources`; explicit matched text and passage/range arrays. The backend exports the completed scan's source result IDs and crawled text. It stores only the crawled text plus `text.comparison.{identical,minorChanges,relatedMeaning}.source.chars.starts/lengths`, discarding HTML, source-document full text and unrelated payload fields. Status projection produces `matching_fragments` containing matched text and, when correctly bound, start/end offsets. Actual source IDs, titles and URLs remain attached.

   Copyleaks' [text-scan guide](https://docs.copyleaks.com/guides/authenticity/detect-plagiarism-text/) separates summary completion from detailed-result export. Its [result schema](https://docs.copyleaks.com/reference/data-types/authenticity/results/new-plagiarism-result/) describes comparison spans; the [crawled-version schema](https://docs.copyleaks.com/reference/data-types/authenticity/results/crawled-version/) supplies the provider's document text.

5. Peer evidence: `peerSimilarity.all_matches[].matching_snippets`, `submission_id`, and `score_percent`, checked against loaded authorized submissions for same classroom/assignment and different student. Clicking a peer highlight exposes Inspect Match and opens the existing detailed comparison modal. No peer essay is inserted into the primary transcription.

6. Mapping: validated exact ranges have priority when bound to the same scanned text. Otherwise, use exact whole-word-boundary passage matching. Ambiguous repeated online text without explicit location/multiplicity is shown in details instead of guessed. Peer phrases reuse the existing case-insensitive consecutive-word mapper. Legacy field aliases are supported without using general snippets/titles as evidence.

7. Overlap: integer ranges are clamped, invalid/reversed ranges removed, and remaining ranges sorted. The renderer divides the essay at range boundaries and attaches all applicable metadata to each flat segment. It produces no nested marks and duplicates no essay text. Overlap identifies “Online + Peer Match.”

8. Canonical text: `submissionTable.transcribed_text` remains the sole full essay displayed. New scan submission preserves its whitespace. Provider UTF-16 coordinates are interpreted against the exported crawled text, with invalid surrogate boundaries rejected. If crawled and canonical text differ, raw offsets are not forwarded; only safely locatable exact passages may highlight. Paragraphs, capitalization, punctuation and Unicode text are not rewritten by the renderer.

9. Editing: stale or mismatched text versions suppress highlights, display “Similarity results were generated before the extracted text was edited,” and retain the explicit Re-run Similarity Check action. New reports rebind highlights to the updated text. Editing, opening and refreshing do not submit new scans. The existing worker requests an export of an already-completed scan, not another scan.

10. Missing/loading evidence: the essay remains readable throughout. Loading is bounded; unavailable evidence leaves the percentage visible with “Exact matching passages are not available for this result.” Unlocatable supplied passages can be opened under “Passages without reliable locations.” Historical summary-only results cannot be reconstructed from a percentage. This change does not automatically backfill or rescan historical records.

11. Theme/accessibility: shared workspace tokens control readable backgrounds/text in both themes. Solid/dotted underline treatments and text labels distinguish match types. Marks have keyboard focus, Enter/Space activation, visible focus outlines, and a contextual source link or peer Inspect Match action. Text remains selectable and Copy text still copies the canonical essay.
