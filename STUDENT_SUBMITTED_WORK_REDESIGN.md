# Student submitted-work redesign

Implemented in the existing frontend. No backend, database, authorization, or submission API changes.

1. **Files/components:** `StudentDashboard.js`, `StudentSubmissionReview.js`, `StudentReviewDialog.js`, `SubmissionFilePreview.js`, `StudentSimilarity.js`, and `studentSubmission.css`. Updated workflow, similarity, and preview tests; added `StudentSubmittedWork.test.js`. Regenerated `workspace-theme.css` using the existing generator.
2. **Duplicate information:** The selected submitted assignment uses its existing page header once. The inner assignment header and its redundant status disappear. The review no longer repeats assignment/classroom names above the work; matching classroom/subject values are deduplicated in the dialog. A distinct student essay title remains available under Submission details.
3. **Hierarchy:** Assignment header and due date → compact submission summary → actual feedback and resubmission action → Your Submission → visible similarity summary → optional submission details/history/comments.
4. **Status:** One current status badge: Submitted, Returned, Resubmission Requested, or Resubmitted. The submitted-detail view no longer displays an additional Turned In badge. Existing assignment-list navigation labels remain intact.
5. **Grade/feedback:** Returned grades, including zero, appear prominently in the summary. Unreleased grades/feedback stay hidden. Ungraded work has a short review state. Missing feedback is one muted line; actual feedback receives a softly shaded panel.
6. **Preview:** Text files have one document surface, readable 16px text, 1.8 line height, a 78-character maximum reading width, responsive scroll height, and keyboard focus. PDF previews remain available and keyboard reachable. The secondary Download submission action uses the existing download icon. Single/multiple image previews retain page downloads, ordering, and lightbox navigation.
7. **Similarity summary:** Percentage and matching-source count are visible without opening a disclosure. Zero is a valid result; pending, failed, unavailable, and classroom-only results retain their separate states. Neutral explanatory wording remains.
8. **Source dialog:** View similarity details opens a portal dialog. Sources are initially expanded inside it, showing title/domain/matched words and an Open source link; raw URLs remain in link destinations. Existing authorized passages and anonymous peer scores remain available. Focus entry, trapping, Escape, close labels, focus restoration, background inertness, and nested-dialog cleanup are covered by tests. Mobile uses almost the full available viewport.
9. **Borders:** Removed the work-section card, nested file card styling, image-figure borders, and borders around secondary disclosures. A document boundary and subtle similarity separators provide structure. Main sections use 22px gaps; document/feedback padding is 20px desktop and 16px mobile. Desktop review width is capped at 1100px.
10. **Navigation overlap:** Retained the existing sticky top header and mobile drawer. There is no fixed bottom navigation to offset. Existing mobile main-content padding includes `5rem + safe-area-inset-bottom`; review dialogs additionally respect safe-area padding and dynamic viewport height. Browser layout checks found no overflow, oversized dialogs, or undersized buttons across review and navigation fixtures. Physical mobile keyboards were not tested.
11. **Resubmissions:** The request reason and existing Resubmit Work action remain before the preview. Current submission retrieval, notification entry, latest-attempt refresh, revision history, archived-class restrictions, first submission, and revision submission flows remain covered by regression tests. Prior attempts stay secondary in history.
12. **Themes:** Existing theme tokens and theme switching are preserved. Browser checks of 15 review fixtures in both themes covered default, expanded, hover, and focus states: **720 states, 14,496 text checks, zero contrast failures, zero horizontal overflow**. Light/dark text and source-dialog screenshots were also inspected.
13. **Viewports:** **360×800, 390×844, 430×932, 768×1024, 1366×768, 1920×1080**, light and dark. The layout audit additionally checked 1024×768: **238 layout checks across 17 fixtures, zero issues**. Evidence is in `artifacts/compact-submission-audit` and `artifacts/compact-submission-layout`.
14. **Validation:** **52 focused tests passed across six suites**, plus the student navigation integration test. These cover the requested A–N states: first awaiting/graded/returned, resubmission requested/awaiting/returned, text/single-image/multipage, zero/one/multiple similarity sources, and absent/present feedback. **Production build passed** with existing unused-variable, duplicate-key, and hook-dependency warnings elsewhere in the application. `git diff --check` passed. See `compact-tests.log`, `compact-navigation.log`, and `compact-build.log` for results. Browser fixtures render real components with mocked services; this verification does not claim live-account/backend or physical-device testing.
